Pierwsza używalna wersja Entrypoint, do własnego użytku i sterowana z CLI: samodzielnie hostowana brama do publikowania usług (HTTP(S) z automatycznym TLS, tunele do aplikacji za NAT-em, wiele replik na serwis).

## Instalacja bramy

```bash
curl -fsSL https://raw.githubusercontent.com/k18k/entrypoint/master/scripts/install.sh | sudo sh
sudo entrypoint install --gateway-name tunnel.example.com --email admin@example.com
```

Wymagania: Linux x86_64 z systemd, porty TCP 80, 443 i 55555.

## SDK Node.js i konektor

```bash
npm install github:k18k/entrypoint-ts#v0.1.0
```

Obraz konektora dla aplikacji w Dockerze: `ghcr.io/k18k/entrypoint-connector:0.1.0`.

## Zawartość

- Routing host+prefiks do upstreamów `IP:port` (np. przez VPN) i do serwisów tunelu; WebSockety, SSE, HTTP/2.
- Tunele frp z tokenami per serwis, prywatnym CA (klient zawsze weryfikuje bramę), odwołaniem tokenów i zrywaniem sesji.
- Drain replik: kontrakt bazowy, adapter `node:http`, CLI i obraz konektora.
- Rewizje konfiguracji z walidacją, rollbackiem i kontrolą dryfu; zaszyfrowany backup i restore.
- Wersje: Caddy 2.11.7, frp 0.71.1 (oficjalne binarki).

Wyniki eksperymentów i testu na prawdziwym serwerze: [docs/wyniki.md](https://github.com/k18k/entrypoint/blob/master/docs/wyniki.md).

## Ograniczenia

- Brama: tylko linux amd64 (ARM64 w v0.2.0). Konektor dla Linux arm64, macOS i Windows się buduje, ale nie ma testów e2e.
- Repliki dzielą ruch po połączeniach TCP, nie po żądaniach.
- Brak panelu i automatycznej aktualizacji (v0.2.0).

## Weryfikacja plików

Sumy SHA256 wszystkich plików są w `SHA256SUMS`; `install.sh` i SDK sprawdzają je przed instalacją.
